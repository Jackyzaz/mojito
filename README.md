# mojito — พรุ่งนี้น้ำจะท่วมไหมนะ?

มินิโปรเจควิชา 240-318 Artificial Intelligence and Machine Learning (วิศวกรรมคอมพิวเตอร์ ม.สงขลานครินทร์)

ระบบพยากรณ์น้ำท่วมอำเภอหาดใหญ่ 3 ส่วนต่อกัน

1. **LSTM** ทำนายระดับน้ำสูงสุดรายวันที่สถานี **X.44 (หาดใหญ่ใน กลางเมือง)** ล่วงหน้า 1–5 วัน
2. **LightGBM + ภูมิประเทศ** แปลงระดับน้ำที่ทำนายได้เป็นความน่าจะเป็นน้ำท่วมของ 1,010 โซนในอำเภอ
3. **เว็บ Flask + Leaflet** แสดงแผนที่ความเสี่ยง ทั้งย้อนดูวันในอดีตและพยากรณ์จากข้อมูลสด

ผลบนชุดทดสอบ (ต.ค. 2568 – ต.ค. 2569 ซึ่งมีน้ำท่วมใหญ่ พ.ย. 2568 พีค 9.97 ม.รทก.)

| | ล่วงหน้า 1 วัน | ล่วงหน้า 5 วัน |
|---|---|---|
| MAE วันน้ำหลาก (ระดับจริง ≥ 4 ม.) LSTM | **0.96 ม.** | **3.31 ม.** |
| MAE วันน้ำหลาก persistence (เดาว่าเท่าวันนี้) | 1.35 ม. | 4.78 ม. |
| เตือนระดับท่วมพื้นที่ลุ่มต่ำ (≥ 7.40 ม.) ถูก | 5 จาก 6 วัน, เตือนผิด 0 | 2 จาก 6 วัน, เตือนผิด 2 |

โมเดลความเสี่ยงรายโซนแยกจุดท่วม/ไม่ท่วมได้ AUC 0.90 (spatial block cross-validation)

## โมเดล

**LSTM ทำนายระดับน้ำ** (`mojito/lstm.py`)
- input: ย้อนหลัง 30 วัน × 7 ค่า = ระยะจากตลิ่งของ 6 สถานีตลอดคลองอู่ตะเภา (X.173A, X.90, X.174, X.44, SLA007, SLA005) + ฝนเฉลี่ยลุ่มน้ำ
- พยากรณ์ฝนรวม t+1…t+h ต่อเข้าหลังชั้น LSTM (ตอนเทรนใช้ฝนที่ตกจริง ตอนทดสอบ/ใช้งานใช้ GFS ที่ปรับ bias)
- ทำนาย **ส่วนต่างจากระดับวันนี้** ของทั้ง 5 วันพร้อมกัน จึงทำนายเกินระดับสูงสุดที่เคยเห็นตอนเทรนได้ (ชุดฝึกสูงสุด 7.26 ม.)
- LSTM hidden 32 → Dropout 0.3 → Linear 32 → ReLU → Linear 5 (6,629 พารามิเตอร์)
- weighted MSE (วันน้ำ ≥ 3 ม. หนัก 5 เท่า), Adam lr 0.001, early stopping patience 15 บนชุด validation
- แบ่งข้อมูลตามเวลา ไม่สุ่ม: train ≤ ธ.ค. 2567, validation ม.ค.–ก.ย. 2568, test ต.ค. 2568 เป็นต้นไป

**แผนที่ความเสี่ยงรายโซน** (`mojito/spatial.py`)
- LightGBM เรียนจาก 5 ค่าภูมิประเทศต่อช่อง 30 ม. (ความสูง, HAND, flow accumulation, ระยะห่างจากลำน้ำ, ความชัน)
  โดยใช้ขอบเขตน้ำท่วมจริงจากภาพเรดาร์ (EOS-RS 23 พ.ย. 2568) เป็น label
- เรียงอันดับความเสี่ยงทั้งเมือง แล้วแปลงเป็น "ระดับ X.44 ที่จุดนี้เริ่มท่วม" (7.40 ม. = ยังไม่ท่วม, 9.97 ม. = ท่วมเท่าภาพดาวเทียม)
- ตอนพยากรณ์: P(ท่วม) = Φ((ระดับที่ทำนาย − ระดับวิกฤต) / σ) เฉลี่ยในแต่ละโซน H3

## โครงสร้าง

```
notebook/              pipeline หลัก 01 → 04
mojito/
  config.py            สถานี ระดับตลิ่ง จุดกริดฝน พื้นที่ศึกษา
  sources.py           ฟังก์ชันดึงข้อมูลแต่ละแหล่ง (ThaiWater, Open-Meteo, Sentinel Asia, Copernicus DEM)
  features.py          ทำความสะอาดระดับน้ำรายชั่วโมง (ค่าแทนข้อมูลหาย, spike, เติมช่องว่าง)
  minimal.py           สร้างตารางรายวัน: ระยะจากตลิ่ง, ฝน, target, split, พยากรณ์ฝน GFS + ตัวแก้ bias
  lstm.py              โมเดล LSTM (PyTorch)
  evaluation.py        ตัวชี้วัด (MAE วันน้ำหลาก, การเตือน 7.40 ม., σ แยกตามระดับ)
  spatial.py           terrain features, ระดับวิกฤต, โซน H3, ความน่าจะเป็นท่วมรายโซน
  realtime.py          โหมดข้อมูลสด: ดึงข้อมูลล่าสุดแล้วสร้างตารางแบบเดียวกับตอนเทรน
  web/                 Flask app (__init__.py), ForecastService (forecast.py), หน้าเว็บ Leaflet
notebooks/archive/     งานทดลองช่วงแรก (Ridge / LightGBM, 46 features) เก็บไว้อ้างอิง
docs/                  รายงาน, บันทึกความคืบหน้า, สำรวจแหล่งข้อมูล
resources/             ขอบเขตอำเภอหาดใหญ่และลุ่มน้ำ (GeoJSON)
data/                  ข้อมูลดิบ ตาราง และโมเดล (สร้างจาก notebook, ไม่อยู่ใน git)
```

## ข้อจำกัด

- เป็นต้นแบบเพื่อการศึกษา ไม่ใช่ระบบเตือนภัยทางการ
- ชุดทดสอบมีน้ำท่วมใหญ่ครั้งเดียว (6 วันที่เกิน 7.40 ม.) ตัวเลขจึงแกว่งได้มาก
- การพยากรณ์ 3–5 วันถูกจำกัดด้วยพยากรณ์ฝนหนักที่ต่ำกว่าจริง (GFS ได้ราว 20–45% ของฝนหนักจริง)
- แผนที่รายโซนเรียนจากภาพน้ำท่วมเหตุการณ์เดียว และสมมติว่าพื้นที่ท่วมเพิ่มเป็นเส้นตรงตามระดับ X.44
